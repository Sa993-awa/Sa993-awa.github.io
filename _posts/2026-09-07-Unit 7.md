## 📝 Initial Post
🟢 The provided Python authentication system had several security vulnerabilities that put users accounts at risk. 
The first issue was that passwords were stored in plaintext. Passwords such as "admin123" and "password" were stored directly, which means that if an attacker gained access to the database, they could read  every password easily. A safer way is to use bcrypt or Argon2 to hash passwords. A salt is also used with password during hashing to make the stored passwords harder to crack.


The second problem is the potential vulnerability to SQL injection attacks. Malicious inputs such as ,`'admin' OR '1'='1'` _even though it does not use a database_ could create a risk in systems that construct SQL queries based on user input. 


In addition, strong password requirements should be introduced, since a poorly chosen password allows the attacker access it directly. And there are some rules for perform a strong password which are addressed by Baker (2022) :

"Password has a minimum length (e.g., nine characters).
"Password contains lowercase letters, uppercase letters, and symbols".
 
 Also, there was no input validation, meaning empty strings or malicious payloads could be accepted.

Finally, rate limiting should be added to restrict repeated failed attempts, avoiding unlimited login attempts. Which allows attackers to carry out brute-force attacks multiple times until they successfully gain accessing.


Refactoring steps : 

Hash password : use bcrypt with a salt to hash the passwords before storing them. 

Secure Authentication : use bcrypt.checkpw to compare the entered password against the stored hash, instead of comparing plain strings. 

Encapsulation: restrict access to sensitive data using private and protected modifiers.

Enforce Password Policies: enforces strong password including minimum length ,lowercase letter, uppercase letter and symbol. 


Add Rate Limiting: reduced the risk of brute-force by limiting the  number of repeated failed login attempts.

``` Python
import bcrypt

class User:
    def __init__ (self,username, password):
        self._username=username
        self._password= bcrypt.hashpw(password.encode(),bcrypt.gensalt())   # Hash and salt the password befor storing it


class AuthenticationSystem:
    def __init__(self):
        self._users=[]
        self._failed_attempts = {}

    def add_user(self,username,password):

        if not username or not password:
            print("Username and password cannot be empty.")
            return False
#check that the password contains lowercase,uppercase and symbol
        if len(password) < 10:
            print("Password must be at least 10 characters.")
            return False
                
        has_lowercase=any(char.islower()for char in password)
        has_uppercase=any(char.isupper()for char in password)
        has_symbol=any(not char.isalnum()for char in password)

        if not(has_lowercase and has_uppercase and has_symbol):
          print( "password must contain lowercase,suppercase and symbol.")
          return False


   #Store the user after the password has been securely hashed
        self._users.append(User(username,password))
        self._failed_attempts[username] = 0

        return True
  
    def authenticate(self,username,password):

        attempts = self._failed_attempts.get(username,0)                     # Adding limit attempts

        if attempts >= 4:           # Limit the number of login attempts to prevent brute-force attacks
            return False

        for user in self._users:
            if user._username==username:

                if bcrypt.checkpw(password.encode(),user._password):
                    self._failed_attempts[username]=0
                    return True
                
                else:         # Compare the entered password with the stored bcrypt hash
                    self._failed_attempts[username] = attempts + 1
                    return False
                
                return False
                

auth_system = AuthenticationSystem()

auth_system.add_user("Sally", "Sally1993@")      # strong password
auth_system.add_user("Sally", "saly1993")        # rejected: less than 10 char, no uppercase and symbol

print(auth_system.authenticate("Sally","sally1993@"))      #First try
print(auth_system.authenticate("Sally","sally1993"))      #Second try

print(auth_system.authenticate("Sally","Sally1993@"))     #Test successful login#
```

Sali, I tested registering "NewUser" twice with a different valid password. It doesn't overwrite the original password the way the issue Reem flagged on my own code did, instead a second account gets silently created with the same username, and only the first one is ever checked when logging in, so the second account's own password never actually authenticates.

Retrying it repeatedly increments the same failed-attempt counter though, and once that reaches the limit, testing confirmed something critical: the original, legitimate "NewUser" account gets locked out too, even with its correct password, since attempts are tracked per username string rather than per individual account. So the missing uniqueness check doesn't just create a dead duplicate, it opens a way to lock a real user out of their own account.

On the password check, complexity is covered but nothing stops password from equaling username outright. Testing add_user("BobSmith1993@", "BobSmith1993@") confirmed it: the call passed every check and the account authenticated successfully afterwards. Baker (2022) lists this exact rule, that a password should not resemble the username, alongside the length and composition rules already implemented here, so it would sit naturally in the same validation block.
