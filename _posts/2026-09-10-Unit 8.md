## Code Smell 1: Magic Number


🟢 One code smell in the original code is the use of _magic numbers_, such as _0.9_ and _0.8_, for the discounts. These values are written directly in the code, which can make it harder to understand what they represent.

For example, someone reading price  0.9 has to work out that this means a 10% discount. It also means that if the discount rate needs to be changed, the code has to be edited directly.

A better approach is to give these values meaningful names to improve readability and maintainability, such as BOOK_DISCOUNT and ELECTRONICS_DISCOUNT. This makes the code easier to read and maintain.    



## Code Smell 2:  Long Method with Conditional Logic

🟢 Another very common smell is the use of an _if-elif-else_ statement to handle the different discount rules. As more types of products are added, this part of the code could become longer and more difficult to manage.

Violetta (2023) addressed that ,the _Long Method_ can become problematic when it starts handling too many responsibilities.
 Ideally, a method should focus on one main task, which relates to the Single Responsibility Principle .

Conditional logic can cause problems when introducing new product types, whenever a new type requires a different discount, a new condition must be added to the existing code. This necessitates constant modification of the current approach, which violates with the "Open-Closed Principle."


The best solution would be to move the various discount rules into separate classes using the "Strategy Pattern", this would make the code more extensible, as new discount strategies could be added without needing to modify the main calculation method. Also the function calculate_total_price no longer decides how a discount is computed , it asks the right strategy.

Refactoring this code in tow way:

1-Using constants (Simple Approach)

```PYTHON

BOOK_DISCOUNT=0.9          # 10% OFF Book Discount
ELECTRONICS_DISCOUNT=0.8   #0.8  # 20% OFF Electronic discount
NO_DISCOUNT= 1.0          # full price No Discount

def calculate_total_price(items):
    total=0
    for item in items:
        if item["type"]=="book":
         total += item["price"] * BOOK_DISCOUNT
        elif item["type"]=="electronics": 
         total += item["price"] * ELECTRONICS_DISCOUNT
        else:
         total += item['price']*NO_DISCOUNT
    return total
```

2- using Strategy Pattern (More Scalable)

```PYTHON
from abc import  ABC, abstractmethod
# for all discount strategies.
class DiscountStrategy(ABC):
    @ abstractmethod
    def apply(self,price):
        pass

class BookDiscount(DiscountStrategy):   #Strategy for applying a 10% discount to books.
 def apply (self,price):                     #appply O/C Principle
      return price *0.9

class ElectronicsDiscount(DiscountStrategy): #Strategy for applying a 20% discount to electronics.
 def apply(self,price):
        return price*0.8  


class NoDiscount(DiscountStrategy):
    def apply(self, price):
        return price
# Strategy used when an item does not have a discount
DISCOUNT_STRATEGY={"book":BookDiscount(),"electronics":ElectronicsDiscount()}

def calculate_total_price(items):
    total=0
    for item in items:
        strategy=DISCOUNT_STRATEGY.get(item["type"],NoDiscount())
        total +=strategy.apply(item["price"])

    return total
```
