🟣 The "Red-Green-Refactor" cycle is a fundamental concept in the Test-Driven Development (TDD) methodology. It represents a robust and structured approach to software development, providing developers with an accurate framework for making incremental progress, the technique is designed to break the development process down into manageable, clear steps, thereby ensuring code correctness and alignment with predefined test requirements.(Agbla, 2024)

2\. 🟢 In this part, I wrote the minimum code needed to pass the test. I created the Addition class with a _static_add method that does not need any object and it can called directly using Addition add without creating an object. 


```Python
import unittest

class AdditionTests(unittest.TestCase):

    def test_add_two_positive_numbers_returns_sum(self):
        
        first_number = 10       
        second_number = 15
        expected_sum = 25

        
        actual_sum = Addition.add(first_number, second_number)

        
        self.assertEqual(expected_sum, actual_sum)



class Addition:
    @staticmethod                 #Minimum implementation to make the test pass
    def add(a: int, b: int) -> int:
        return a + b


if __name__ == "__main__":
    unittest.main()
```

3\. 🔵 After that,  I moved to the Refactor step, and make it cleaner and easier to understand.
 I also create a clear test names like_test_add__two__positive_numbers_returns_sum. Then I add two more test cases to cover additional behavior ,such as adding a negative number ad adding zero, which shows an edge case and most software bugs come from it. I rerun all three test again , they still passed . This confirms that I improved the code keeping its behavior. 

```Python

import unittest

class Addition:
    @staticmethod
    def add(a: int, b: int) -> int:
        """Return the sum of two integers."""
        return a + b

 
class AdditionTests(unittest.TestCase):

        def test_add_two_positive_numbers_returns_sum(self):
        
         actual_sum = Addition.add(10, 15)

         self.assertEqual(25, actual_sum)


        def test_add_negative_number_returns_correct_sum(self):
        
          first_number, second_number, expected_sum = 10, -3, 7
      
          actual_sum = Addition.add(first_number, second_number)
     
          self.assertEqual(expected_sum, actual_sum)          


        def test_add_zero_returns_same_number(self):                                 #Edge Case
        
         first_number, second_number, expected_sum = 5, 0, 5
        
         actual_sum = Addition.add(first_number, second_number)
        
         self.assertEqual(expected_sum, actual_sum) 

          

if __name__ == "__main__":
    unittest.main()        
```

🟢🔴🔵 During  the test, we define a condition and specify what we expect when that condition is met. We begin with the baseline condition, also known as the positive or happy path. We complete all the positive paths first before moving on to the other conditions.(Tibi,2022)
