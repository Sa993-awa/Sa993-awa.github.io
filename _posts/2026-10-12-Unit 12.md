### Advanced Design Patterns (Practical)


``` Python
from abc import ABC, abstractmethod

#Interface
class DiscountStrategy(ABC): 
    @abstractmethod
    def calculate(self,price:float):
        pass

class StudentDiscount(DiscountStrategy):
    def calculate(self,price:float):
        return price *0.3       # 70% Discount

class NonStudentDiscount(DiscountStrategy):
    def calculate(self,price:float):
         return price  *0.5      # 50% Discount

class ShoppingCart:
    def __init__(self,strategy:DiscountStrategy):
        self.strategy=strategy     

    def get_final_price(self,price:float):
        return self.strategy.calculate(price)  

cart_student= ShoppingCart(StudentDiscount())    
print(cart_student.get_final_price(200))

cart_nonstudent=ShoppingCart(NonStudentDiscount())
print(cart_nonstudent.get_final_price(200))
```
🟢 In this system The Strategy Pattern was implemented to manage different discount calculation algorithms in the shopping cart system. The *DiscountStrategy* class provides a common interface, while *StudentDiscount* and *NonStudentDiscount* provide different implementations of the discount calculation.


The Strategy Pattern was chosen in this case because the shopping cart needs to switch between  different discount  strategy without changing its own code. Instead of appling all discount rules inside the *ShoppingCart* class, each discount algorithm is separated into its own strategy.

This improves **maintainability** because each discount calculation is contained in a separate class, making the code easier to understand and modify. It also improves **extensibility**, because new discount types can be added by creating another strategy class without modifying the existing *ShoppingCart*. For example, a *VipDiscount* strategy could be added in the future.

Also,**testability** had been improved because each discount strategy can be tested independently to ensure that its calculation produces the expected result.




```python
from abc import ABC, abstractmethod

class FacebookPost(ABC):
    @abstractmethod
    def publish(self,content):
        pass

class BasicPost(FacebookPost):
    def publish(self,content):
        print(f"Post Published:{content}")
        


class PostDecorator(FacebookPost):
    def __init__(self,post):
       self.post= post


class SecurityDecorator(PostDecorator):
    def publish(self, content):
        print("Security check has been completed.")
        return self.post.publish(content)

    
class LoggingDecorator(PostDecorator):
    def publish(self, content):
        print("Post is being published.")
        return self.post.publish(content)

class ModerationDecorator(PostDecorator):
    def publish(self, content):
        print("Content moderation has been completed.")
        return self.post.publish(content)

class UploadingPhotoDecorator(PostDecorator):
    def publish(self,content):
        print("Photo has been uploaded!")       
        return self.post.publish(content)

#create basic post
post=BasicPost()

#Dynamically add functionality
post=SecurityDecorator(post)
post= LoggingDecorator(post)
post=ModerationDecorator(post)
post=UploadingPhotoDecorator(post)

#publish the post
post.publish("Welcome To Facebook")
```






🟢In this system the Decorator Pattern was used to extend the functionality of a **Facebook** post.  The LoggingDecorator applied request logging, while the SecurityDecorator applied a security checking layer. These features can be added to the FacebookPost without modifying the original BasicPost class. I have extended the functionality by adding UploadingPhoto class to support the idea of the 
Decorator pattern of Dynamically extending functionality.


This improves *maintainability* because Logging and security are separated from the core BasicPost.  It also improves *extensibility* 
as additional decorators, such as uploading photo and AuthenticationDecorator can be added without modifying the existing Facebook post.

*Testability* had been applied to this system as each decorator can be tested independently to check that its additional functionality works correctly.
