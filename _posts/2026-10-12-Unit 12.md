### Advanced Design Patterns (Practical)
``` Python
from abc import ABC, abstractmethod

#Interface
class DiscountStrategy(ABC): 
    @abstractmethod
    def calculate(self,price:float):
        pass

class StudentDiscount(DiscountStrategy):
    def calculate(self,price:float):
        return price *0.3       # 70% Discount

class NonStudentDiscount(DiscountStrategy):
    def calculate(self,price:float):
         return price  *0.5      # 50% Discount

class ShoppingCart:
    def __init__(self,strategy:DiscountStrategy):
        self.strategy=strategy     

    def get_final_price(self,price:float):
        return self.strategy.calculate(price)  

cart_student= ShoppingCart(StudentDiscount())    
print(cart_student.get_final_price(200))

cart_nonstudent=ShoppingCart(NonStudentDiscount())
print(cart_nonstudent.get_final_price(200))
```
🟢 In this system The Strategy Pattern was implemented to manage different discount calculation algorithms in the shopping cart system. The *DiscountStrategy* class provides a common interface, while *StudentDiscount* and *NonStudentDiscount* provide different implementations of the discount calculation.


The Strategy Pattern was chosen in this case because the shopping cart needs to switch between  different discount  strategy without changing its own code. Instead of appling all discount rules inside the *ShoppingCart* class, each discount algorithm is separated into its own strategy.

This improves **maintainability** because each discount calculation is contained in a separate class, making the code easier to understand and modify. It also improves **extensibility**, because new discount types can be added by creating another strategy class without modifying the existing *ShoppingCart*. For example, a *VipDiscount* strategy could be added in the future.

Also,**testability** had been improved because each discount strategy can be tested independently to ensure that its calculation produces the expected result.
