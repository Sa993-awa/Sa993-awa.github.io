First, I expalined the Concurrency and the parallelism meaning.
Concurrency means managing multiple tasks during the same period of time. The tasks can take turns running, while Parallelism means executing multiple tasks at the same time.
  
I created two threads. The first thread performs deposits, and the second thread performs withdrawals.
Both threads use the same bank account, so they are accessing shared data.

The class stores the account balance and provides two main operations: deposit and withdrawal.

I use encapsulation in my BankAccount class This helps control how the balance is accessed and changed.

Morover , I use abstraction.For example, when I call the deposit method, I don't need to know all the internal details of how the balance is changed or how the lock works.The method hides these implementation details from the user.

Returning back to the threads , the first one  runs the deposit function. 
The second thread runs the withdrawal function. 

The target parameter tells each thread which function it should execute.

When I call start(), the thread begins executing its target function.

At the end, I use join() so that the main program waits for both threads to finish before printing the final balance.

There are many concurrency problem. According to an explanation provided by (Nguyen, 2022) a race condition happens when multiple threads access and modify the same shared data at the same time, and the final result can depend on the timing of the threads.



In my example, both threads access the same bank account and therefore the same balance.
If both threads try to change the balance at the same time without protection, one operation could interfere with the other and produce an incorrect result.

To solve this problem, I use a lock.This means only one thread can execute the protected section at a time.
When one thread gets the lock, the other thread has to wait. When the first thread finishes, the lock is released and the other thread can continue.

Another common concurrency problem is a deadlock. A deadlock occur when two or more threads are waiting for each other for ever, so none of them can continue.
Another  synchronization mechacnism is a semaphore. A semaphore can allow a specified number of threads to access a resource simultaneously.

In my bank account example, a lock is more appropriate because changing the balance should be done by one thread at a time.
Finally, the join() means to wait for both threads to finish.

I also import time module. The time.sleep(0.01) using to pause each thread making the concurrent execution easier to observe. It does not prevent race conditions or deadlocks, the lock is responsible for protecting the shared balance.

I included one commentary about the thread safety : imagain there is a bank account and the balance is 100£، and 2 users want to withdraw 50£ each the result will be incorrect  so the lock prevent race condition by ensuring that only one thread can access and change the balance.

```Python
import threading
import time

class BankAccount:
    def __init__(self,balance):
        self.balance=balance
        self.lock=threading.Lock()


    def deposit(self,amount):
        with self.lock:
            self.balance+=amount

    def withdraw(self,amount):
        with self.lock:
           if self.balance>=amount:
               self.balance-=amount

account=BankAccount(500)               #Create a BankAccont object


def deposit_money():
    for i in range (10):
        account.deposit(50)
        time.sleep(0.01)

def withdraw_money():
    for i in range(10):
        account.withdraw(10)
        time.sleep(0.01)

t1= threading.Thread(target=deposit_money)
t2= threading.Thread(target=withdraw_money)

t1.start()
t2.start()

t1.join()
t2.join()

print("Final Balance:",account.balance)
```
