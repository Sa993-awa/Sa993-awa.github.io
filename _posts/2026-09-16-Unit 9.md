class Cache(ABC):
    @abstractmethod
    def get(self, key):
        pass

    @abstractmethod
    def set(self, key, value):
        pass

# Scalable implementation 
class RedisCache(Cache):         
    def __init__(self):

        self.__cache = {}

    def get(self, key):

        return self.__cache.get(key)

    def set(self, key, value):

        self.__cache[key] = value

    def add_product(self,product: Product,quantity: int = 1):

        if quantity <= 0:

            return False

        product_id = product.get_product_id()

        if product_id in self.__products:

            self.__products[product_id]["quantity"] += quantity

        else:

            self.__products[product_id] = {"product": product,"quantity": quantity }

        return True
    

    def get_product(self, product_id: str):

        return self.__products.get(product_id,{}).get("product")

    def check_stock(self, product_id: str):

        return self.__products.get(product_id,{}).get("quantity", 0)

    def reduce_stock(self, product_id: str,quantity: int):

        if self.check_stock(product_id) >= quantity:

            self.__products[product_id]["quantity"] -= quantity

            return True

        return False    


class User(ABC):
    def __init__(self,user_id: str,name: str,password: str):

        self.__user_id = user_id
        self.__name = name

        # Password is stored as a bcrypt hash.
        self.__password_hash = bcrypt.hashpw(password.encode(), bcrypt.gensalt())

    def get_user_id(self):

        return self.__user_id

    def get_name(self):

        return self.__name

    def check_password(self, password):

        return bcrypt.checkpw(password.encode(),self.__password_hash)

    @abstractmethod
    def get_role(self):

        pass

    def __str__(self):

        return f"{self.__name} ({self.get_role()})"

class Customer(User):

        super().__init__(user_id,name,password )

        return "Customer"

    def add_to_cart(self,product: Product, quantity: int = 1):

        if quantity <= 0:

            return False

        self.__cart.append({"product": product, "quantity": quantity})

        return True

    def view_cart(self):

        return [f"{item['product']} x{item['quantity']}" for item in self.__cart]

    def get_cart(self):

        return self.__cart

    def calculate_cart_total(self):

        total = 0

        for item in self.__cart:

            total += ( item["product"].get_price()* item["quantity"])

        return total

class ProductService:
      def __init__(self,product_repository: ProductRepository,cache: Cache):

        self.__repository = product_repository
        self.__cache = cache

      def get_product(self, product_id):

        # Check cache first
        product = self.__cache.get(product_id)

        if product is not None:

            return product

        # If product is not cached, retrieve it
        # from the repository.
        product = self.__repository.find_by_id(product_id)

        if product is not None:

            self.__cache.set(product_id,product)

        return product

      def get_all_products(self):

        return self.__repository.find_all()

class OrderNotifier:

    def notify(self, order):

        for subscriber in self.__subscribers:

            subscriber.update(order)

🟢 This report explains the design of ShopEase, *an online shopping system for e-commerce company*, which can handle a large number of users, products, and transactions while ensuring scalability, maintainability, and security.

 The system relies on a layered design, object-oriented software architecture and established design patterns.

The system follows a three-layer structure to organize functionality into three layers ,which keeps the modules loosely coupled and highly cohesive so they remain testable and maintainable (Chow,2024). 

The Presentation Layer(ShopEase) which handles user interaction and produces data to the user, while the Business Logic Layer (UserService, ProductService, AuthenticationService) holds the core rules, and the Data Access Layer (the repository classes) manages data storage. Because business logic depends on repository abstractions rather than concrete storage, the database can be replaced without rewriting the services.

The system is divided into three independent modules for user management, product catalogue, and order processing. 

Each part applies the four OOP principles: encapsulation  to enforce security (private attributes with getters), inheritance (Customer extend User), polymorphism (each PaymentStrategy provides its own pay()), and abstraction (abstract base classes). This modularity shows the single responsibility principle, where each part has one reason to change.

The scalability requires in this task and it has been shown in the RedisCache  which sits in front of the ProductRepository, and it reduces repeated database reads, reflecting how caching and independent scaling improve performance. Also, it supported through the Strategy Pattern when payment had been applied and dependency injection, where services receive their repository rather than creating them.

The Observe pattern decouples notifications, allowing new channels to subscribe without altering the ordering logic, while the Adapter  Pattern encapsulates legacy code to facilitate safe updates.


The Security has been implemented  in this system, using hashed passwords using bcrypt. Authentication is isolated in a dedicated service , protecting sensitive data from direct exposure.

overall, this ShopEase achieves maintainability, security and extensibility design by combining layered architecture with proven patterns suited to growing e-commerce platform.
